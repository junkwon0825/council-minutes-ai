# 생성형 AI 활용 및 검토 기록

## 활용 도구

- 로컬 LLM: Ollama `qwen3:8b`
- 개발 보조 AI: 문제 구조화, 코드 초안, 오류 진단, 문서 작성 지원

## 활용 단계

- 문제 요구사항과 제출 형식 정리
- 데이터 처리·임베딩·군집화 파이프라인 설계
- Python 코드 초안 및 오류 원인 분석
- 모델 후보와 예측 방법 비교
- README, 실행 가이드, 발표 자료 구조화

## 참가자 주요 기여 및 검증

- 데이터 스키마와 실제 오류를 직접 확인
- 필터 조건과 제외 샘플을 검토해 정책 후보 규칙 수정
- 청킹 결과와 검색 결과를 표본 검수
- 군집 수와 대표 발언의 일관성을 비교
- LLM 결과에 근거 비율과 이상치 검사를 추가
- 시간순 검증 결과에 따라 예측 모델 채택 여부 결정
- 최종 결과의 원문 근거와 날짜 연결을 검증

## 검토한 대안과 실패 사례

- 모든 회의록을 LLM으로 처리: 처리 시간·자원·환각·재현성 문제로 미채택
- 전체 청크를 바로 군집화: 회의 진행성 문장이 섞여 정책 전용 부분 집합으로 변경
- 긴 부모 청크만 임베딩: 여러 정책 혼합 문제로 의미 자식 청킹 추가
- K=100: 군집이 넓어 K=160 대안 검토
- LLM 판정만 신뢰: 과도한 coherent 판정을 발견해 코드 품질 게이트 추가
- 예측 모델 무조건 적용: 검증 성능 미달 시 규칙 기반 대체로 변경

## 최종 선택 이유

임베딩 기반 검색·군집화는 전체 데이터에 같은 기준을 적용할 수 있고, 로컬 LLM은
이름 제안 역할로 제한해 외부 전송과 환각 위험을 줄일 수 있다. 예측은 시간순 검증과
성능 게이트를 적용해 성능이 확인된 모델만 사용한다.
