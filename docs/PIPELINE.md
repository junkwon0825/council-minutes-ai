# 전체 분석 파이프라인

## 목표

제공된 2024~2025년 광역 지방의회 회의록만 이용해 다음 결과를 생성한다.

1. 주요 정책 이슈명과 핵심 키워드
2. 제공 데이터 범위 내 최초 관측일
3. 다른 지방의회의 후속 논의 순서
4. 월별 논의량과 참여 의회 변화
5. 분석 기준일 다음 달의 논의 방향과 신규 의회 확산 가능성
6. 모든 결과를 뒷받침하는 회의록명·일자·원문 구간

## 단계별 구성

| 단계 | 파일 | 입력 | 핵심 처리 | 출력 |
|---:|---|---|---|---|
| 01 | `01_inventory.py` | 원본 JSON 36개 | 인코딩·스키마·레코드·날짜 점검 | 인벤토리 CSV/JSON |
| 02 | `02_preprocess.py` | JSON 내부 HTML | HTML 정제, 공백 정규화, 완전 중복 제거 | `documents.parquet` |
| 03 | `03_make_chunks.py` | 정제 문서 | 안건·발화·문단 경계 기반 부모 청킹 | `chunks.parquet` |
| 04b | `04b_issue_embedding.py` | 부모 청크 | 정책 후보 필터와 제외 사유 기록 | 후보 Parquet |
| 04c | `04c_issue_relevance.py` | 정책 후보 | 정책 관련성 점수·사유 계산 | 선택 후보 |
| 04e | `04e_semantic_text.py` | 긴 부모 청크 | 군집화용 의미 자식 청크 생성 | 의미 청크 |
| 04d | `04d_embed_selected.py` | 의미 청크 | 한국어 임베딩, L2 정규화, float16 저장 | NPY·메타데이터 |
| 05 | `05_build_faiss.py` | 정규화 임베딩 | 정확 내적 검색 인덱스 구축 | FAISS 인덱스 |
| 06 | `06_search_v2.py` | 검색어·FAISS | query prompt, 중복 제거, 근거 반환 | 검색 결과 |
| 07 | `07_clustering.py` | 정책 임베딩 | MiniBatchKMeans, 대표 발언·키워드 | K=160 군집 |
| 08 | `08_llm_issue_labeling.py` | 군집 대표 발언 | 로컬 LLM 이슈명 제안·품질 게이트 | 검수 라벨 |
| 09 | `09_build_issue_timeline.py` | 라벨·군집 배정 | 최초 관측·후속 의회·월별 변화·원문 결합 | 이슈 타임라인 |
| 10 | `10_issue_query.py` | 검색어·타임라인·예측 | 검색어를 군집 중심에 연결 | 통합 검색 JSON |
| 11 | `11_forecast_issue_flow.py` | 월별 이슈 시계열 | 시간순 검증·모델 비교·성능 게이트 | 다음 달 예측 |

## 부모–자식 청킹

- 부모 청크는 회의 문맥과 원문 위치를 보존한다.
- 자식 청크는 서로 다른 정책이 한 벡터에 섞이지 않도록 의미 단위를 짧게 만든다.
- 검색·군집화는 자식 벡터를 사용한다.
- 최종 근거는 `parent_chunk_id`, `doc_id`, `evidence_ref`, 문자 범위를 통해 원문으로
  연결한다.

## 이슈 확정 과정

1. KMeans가 유사 발언을 후보 군집으로 묶는다.
2. TF-IDF 키워드와 중심에 가까운 대표 발언을 뽑는다.
3. Qwen이 각 대표 발언의 개별 주제와 군집의 지배 주제를 제안한다.
4. 대표 발언 중 같은 이슈를 직접 지지하는 번호와 이상치 번호를 분리한다.
5. 동일 이슈 지지율이 75% 미만이면 코드가 `mixed`로 처리한다.
6. 검수된 `accepted_candidate`만 고정 `issue_id`를 부여한다.

LLM은 군집을 만드는 모델이 아니라 사람이 이해할 수 있는 이름과 설명을 제안하는
보조 모델이다. 군집 자체는 임베딩과 KMeans로 생성된다.

## 최초 관측과 후속 논의

- 최초 관측일: 해당 이슈로 인정된 근거 중 가장 이른 회의일
- 최초 의회: 최초 관측일과 같은 날짜에 등장한 모든 의회
- 후속 순서: 의회별 최초 관측일을 시간순으로 정렬한 순서
- 시차: 전체 최초 관측일과 각 의회 최초 관측일의 날짜 차이
- 중복 방지: 같은 이슈·의회·날짜·부모 청크는 한 번만 계산

이는 시간적 관측 순서이며 정책이 한 의회에서 다른 의회로 직접 전달됐다는 인과관계를
증명하지 않는다.

## 예측 구조

예측 단위는 검수된 이슈의 다음 달 상태다. 입력에는 제공 데이터에서 계산한 다음
변수만 사용한다.

- 현재·최근 평균·이전 평균 언급량
- 최근 언급량 모멘텀과 선형 기울기
- 최근 활동 월 비율
- 최근 참여 의회 수와 신규 의회 수
- 17개 의회 대비 누적 확산률
- 마지막 언급 이후 경과 월
- 이슈가 관측된 기간

로지스틱 회귀를 설명 가능한 기준 모델로 두고 LightGBM과 비교한다. 마지막 4개월을
검증 구간으로 고정하며 F1과 balanced accuracy가 기준을 통과한 모델만 사용한다.
성능이 부족하면 최근 추세를 이용하는 규칙으로 대체하고 신뢰도를 낮게 표시한다.
