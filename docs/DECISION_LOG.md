# 주요 의사결정 기록

| 결정 | 검토한 대안 | 최종 선택 이유 |
|---|---|---|
| Ubuntu/WSL 중심 환경 | 조원 전원 Windows 네이티브 | CUDA·Python 경로 재현성이 좋고 Windows 사용자는 WSL로 통일 가능 |
| 임베딩 기반 이슈 발견 | 모든 회의록을 LLM에 넣어 발화·이슈 추출 | 비용과 시간, 재현성, 환각 문제를 줄이고 전체 데이터에 일관된 벡터 기준 적용 |
| 부모–자식 청킹 | 고정 길이 단일 청킹 | 부모는 원문 문맥, 자식은 검색·군집 의미 순도를 담당 |
| 별도 정책 전용 임베딩 | 전체 46만 청크만 사용 | 회의 진행·인사·명단 잡음을 줄이면서 전체 인덱스는 검색용으로 보존 |
| FAISS IndexFlatIP | Chroma, 양자화 인덱스 | 2.5만 정책 벡터에서는 정확 검색이 충분히 빠르고 결과 설명이 단순 |
| MiniBatchKMeans K=160 | K=100, 밀도 기반 군집 | 대용량 처리 가능, 빈 군집 없이 더 구체적인 정책 단위 형성 |
| Qwen3 8B 로컬 | 외부 API, EXAONE, Gemma | 외부 전송 금지 준수, 한국어 처리, 로컬 GPU 가용성과 구조화 출력의 균형 |
| LLM은 이름 제안만 수행 | LLM이 전체 이슈 분류 | 임베딩 군집의 재현성을 유지하고 LLM 환각 영향 제한 |
| 로지스틱+LightGBM 비교 | LLM 단독 미래 예측 | 정량 시계열 근거와 시간순 검증 성능을 제시 가능 |
| 성능 미달 시 규칙 대체 | 무조건 최고 점수 모델 사용 | 검증 성능이 낮은 모델을 과장하지 않고 결과 신뢰도를 명시 |
| Streamlit 데모 | 정적 PPT만 제출 | 검색–지도–타임라인–근거를 한 화면에서 재현 가능 |

## 아직 개선할 부분

- 사람 검수 라벨을 늘려 군집 순도 평가용 정답 세트 구축
- 의미 청크 크기와 K값에 대한 정량 비교 실험 확대
- 이슈 동의어 사전과 한국어 형태소 기반 키워드 개선
- 신규 의회 확산 양성 표본 확보와 예측 검증 강화
- 지도에 행정구역 GeoJSON을 로컬 자산으로 포함하되 외부 데이터 사용 조건 검토
- 실제 정책 인과 전파와 단순 동시 발생을 구분하는 연구 설계
